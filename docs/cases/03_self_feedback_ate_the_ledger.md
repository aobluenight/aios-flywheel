# 判例 03 · 自反馈飞轮吃掉自己的账（增量台账+覆盖保护的由来）

> 脱敏自真实产线。

## 事故

一条"产物→入库→统计→回流到下一轮输入"的自反馈飞轮，某次上游格式变更后，入库步骤开始把"本轮统计结果"写进同一个聚合文件——**覆盖而不是追加**。数周内历史账目被逐轮稀释，最终统计口径整体失真。整个过程没有报错、退出码全绿：**静默劣化**。

## 根因

1. 写路径存在"覆盖语义"，而该文件承载不可变历史——语义与用途错配。
2. 没有任何机制区分"追加一笔"与"重写全部"。

## 沉淀（core/ledger.py 两条纪律）

1. **历史账一律 AppendLedger（JSONL 只增）**：append 自动盖时间戳+schema_version；改写历史行在 API 层面不存在。
2. **所有"写文件"过覆盖保护闸（guard_overwrite）**：refuse（默认，已存在即拒）/ sidecar（写带时间戳的兄弟文件）/ backup（旧文件挪 .bak）。想覆盖必须显式选策略并留下痕迹——`truncate` 覆盖在这个库里没有语法。
3. 衍生体检规则：增量判定（件套①的 `json_metric`）盯"账是否还在长"——账停了或倒退，飞轮病了。

## 对应件

`core/ledger.py::AppendLedger` / `guard_overwrite`，`tools/ledger.py`
