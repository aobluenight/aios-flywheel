# 判例 04 · 字符集外的一个对勾，部署即炸（坑→门禁的由来）

> 脱敏自真实产线。这是"坑→判例→门禁"路径的首例实证：同族坑第一次靠机器拦下，而不是靠人记性。

## 事故

部署器把源码文件从 UTF-8 转换到目标平台的遗留字符集（GBK）后下发。某次改稿时开发在提示文案里用了一个对勾符号「✓」——UTF-8 里岁月静好，转码时目标字符集字表里没有这个字，**部署在用户机器上炸掉**。之前还有「↔」出过同族事故。

## 处置

1. 修复：换字表内字符。
2. 沉淀为门禁规则：`pattern: [✓✗↔▶]`，作用域 `**/*.lua`，severity=block——**在转换发生前的源头上拦**，message 里带判例编号，人人知道为什么拦。
3. 之后一次改稿又想用「✓」，门禁当场拦下，改「完成！」——同族坑第二次出现时，成本为零。

## 纪律

- 门禁规则永远由真实坑沉淀而来（message 可回溯判例）；**禁凭空发明规则**——没有事故背书的规则只会训练人绕过门禁。
- 坑的 lifecycle：事故 → 根因 → 规则入 yaml → 门禁在预检/CI 挂载 → 同族坑自动拦。
